# Real blots — the Gate 2 set

PLAN.md's Gate 2: *"approve the real-image list — CC-BY figures only, DOI + license recorded
per image."* This directory is that set. It is the first data in this project that was not
generated by `synth/`, and the first that can address DEBT S1 — the generator has never been
validated against a real blot.

**Nothing here has been measured yet.** Gate 2 approved the *list*; the ImageJ comparison is
Phase 3 work that follows.

## What is committed, and why it is not everything

**The 19 crops are committed without argument.** They are the measured artefacts. §9 of the
pre-registration requires that *"ImageJ runs on the SAME crop file, byte-identical"*, so a
comparison whose crops are not fixed in the tree is not reproducible at all.

**13 of the 21 source figures are committed: exactly those a crop derives from.** The rule is
`committed == yes` in `sources.csv`. Two reasons, and the second is the load-bearing one:

1. §9 makes the parent linkage the crop's audit trail — *"the parent linkage makes the crop
   auditable against its source"*. An audit trail whose far end is a URL is only as durable as
   someone else's website.
2. **Recovery is genuinely fragile, and measurably so.** PMC serves figures from a CDN path
   with an opaque per-blob hash that cannot be constructed from anything recorded; the URL has
   to be re-read from the live article page each time (`tools/gate2/README.md` sets out why).
   If a publisher re-renders a figure, the sha256 changes and the parent is gone. Committing
   2.5 MB against that is cheap, and `data/images/` (1.9 MB of committed gold set) is the
   precedent: it is committed so *"every later phase measures against a byte-identical set"*.

**The other 8 are not committed.** No crop derives from them, so nothing measures them, and a
committed file nothing depends on is a file a reader learns to ignore. They remain fully
recorded in `sources.csv` and recoverable:

```
python tools/gate2/refetch_sources.py --only uncommitted --out /tmp/recovered
```

That command is the reconstruction, not a description of one. It re-resolves each figure's CDN
URL from its article page, downloads it, and **verifies the bytes against the recorded
sha256**, failing loudly if upstream has changed. `--only committed` runs the same check
against the 13 here and additionally compares them to the committed copies. It needs network
and is deliberately not a CI step; CI verifies the committed bytes instead, which needs none.

**Verified live on 2026-08-18: 21 of 21.** All 8 uncommitted sources were recovered and matched
their recorded sha256, and all 13 committed sources were re-verified against upstream and found
byte-identical to the copies here. The first run had failed on all 8 with
`CERTIFICATE_VERIFY_FAILED` — TLS interception on the operator's network, not a PMC failure — which
is why the tool builds its `SSLContext` from `certifi`; verification is not disabled, because
hashing bytes from an unauthenticated connection would prove only that they match what someone
served.

**This confirms the premise held on one day; it does not retire the reason for committing the 13.**
Recovery depends on publishers continuing to serve byte-identical bytes, and the point of
committing was always that they can stop without notice. A future run that fails is a finding
about upstream, not about this set.

## The pre-registration is frozen, and is not restated

`DECISION_unit_of_analysis.md` is committed **byte-identical** to the file Gate 2 froze:

```
sha256 = 994acc30daf82011acfe957adff2866f824b05aa3b39bade118e539f4cfd88d0
```

It was written outside the repository and frozen before any measurement, and that hash is
cited. So it is imported unchanged rather than folded into NOTES.md — NOTES.md records
decisions in its own voice, and rewriting a pre-registration into that voice would destroy the
one property that makes it a pre-registration. NOTES.md points at it and does not paraphrase
it; `tools/check_claims.py` re-verifies the hash on every CI run, so an edit to this file fails
the build.

Note §11a: one crop (`PMC13135388_Figure4__E-Vinculin`) was re-cropped after §11, and §11's
stated colour-fraction maximum of 0.0158 refers to the superseded crop. The current set maximum
is 0.0068. `crop_log.csv` holds the current crop's sha256.

## Licensing

Every figure is CC BY, with DOI, journal, year and licence recorded per image in
`provenance.md` and `sources.csv`. **The repository's MIT licence does not cover them** — they
are third-party published figures carrying their own terms, and the crops are derivative works
of them under the same terms. This is the distinction NOTES.md draws under "Licence: MIT,
chosen by the human — and it does not reach third-party figures".
