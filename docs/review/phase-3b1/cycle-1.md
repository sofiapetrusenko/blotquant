## SUGGESTED

- `pipeline/load.py::channel_divergence_dn` is public and does `array.astype(np.int32)` with no dtype gate; called directly on float or int64 data it would truncate rather than raise. The shipped path is safe because `_collapse_channels` checks dtype first, but the public function's contract does not say so.
- `pipeline/load.py::_collapse_channels`, bit-depth branch: for a 3-channel **float32** input the message says "defined only for 8-bit input … Export a single channel", which misdirects — a single float32 channel then raises `UnsupportedBitDepthError`. The 16-bit case the message was written for is fine.
- `tests/test_real_channel_collapse.py:141`: `named = [value for value in range(3, 44) if f"{value} DN" in message]` is weaker than it reads — `"43 DN"` contains the substring `"3 DN"`, so `named` is `[3, 43]` for that crop and `assert named` would survive a fairly large drift. Parse the integer out of the message and assert `&gt;= 3` instead.
- `measurable_crops` reads crop bytes without verifying `crop_sha256` from the frozen log, while `tools/phase3/run_real.py` explicitly does ("refuses to measure a crop whose bytes do not match its recorded `crop_sha256`, because §9"). Both committed tables and the real-set regression derive from unverified bytes. Partly mitigated by the exact `== 0` / `== 2` divergence assertions.
- `CROP_LOG_PATH`, `DESIGNATIONS_PATH`, `BLOT_IDENTITY_PATH` and `tests/test_real_channel_collapse.py:CROPS` are relative paths, making the tools and the new tests cwd-dependent. Other tests use a `repo_root` fixture.
- `schema/result.schema.json:5` — the top-level description still narrates the contract only through 1.2.0 and does not mention `channel_collapse`.
- `api/app.py:69` (and the OpenAPI text) enumerates `result_id`'s inputs as four. There are now five. No user-visible inaccuracy yet, since the API cannot vary the fifth, but the enumeration is now incomplete.
- Every 1.2.0-era `result_id` changes under 1.3.0, because `|null` is appended unconditionally in `_result_id`. Harmless — the `schema_version` const already rejects stored documents — but worth a sentence in NOTES.md beside the bump reasoning rather than left for someone to discover.
- `test_the_collapse_takes_green_and_not_a_neighbouring_plane` writes and reads its fixture with the same library (cv2), so it pins "index 1" rather than "the file's green channel". It happens to be sound because green is the middle plane under both RGB and BGR, but a fixture written with `tifffile` and read back through the loader would test the claim independently. No real crop is asserted to have taken green specifically — the two at-the-bound crops assert only `max_divergence_dn == 2`.
